# v0.1.1 商家后台接口变更（#11）

日期：2026-10-19
关联：`specs/03-api.md` §1.3 / §6.4 / §8.1-8.3，issue #11

## 变更内容

| 接口 | 变更 | 原因 |
|---|---|---|
| `GET /api/v1/admin/orders/:id` | 新增 | 后台订单详情页需要单笔详情，顾客端 `GET /orders/:id` 不校验门店归属，不能复用 |
| `DELETE /api/v1/admin/printers/:id` | 新增 | §8 原本只有列表与添加，配置页需要移除换错的打印机 |
| `POST /api/v1/admin/orders/:id/print` | 请求体新增可选 `printerId` | 门店可配置多台打印机（前台/后厨），原实现固定取第一台 |
| 商家端全部接口 | query/body 中的 `merchantId` 必须与 token 一致 | 单店模板下仍属越权面，统一在 `AdminAuthGuard` 拦截 |
| `POST /payment/wx-notify` | 支付成功后补发 `order:new` 事件 | §9.2 定义了该事件但服务端无发布者，后台「实时新单提醒」收不到推送 |
| §9.1 WS 连接方式 | 文档改为「统一 `/ws` + 订阅消息进房」 | 原文的 `/ws?token=` 与 `/ws/admin` 从未实现，顾客端（#10）与后台均按 `{event:'subscribe:*'}` 协议工作 |
| 后台订单详情按钮 | `ready`（可取餐）不再提供「取消订单」 | 状态机 `ready` 只能流转为 `completed`/`refunding`，此前前端给出的按钮必然返回 `2002` |

## 兼容性

- 全部为新增接口或新增可选字段，旧客户端不受影响。
- 未携带 `merchantId` 的商家端请求行为不变。
- 跨门店访问：订单返回 `1003`，打印机返回 `1004`（不暴露资源是否存在）。
