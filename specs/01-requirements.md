# 01 - 需求规格（Requirements）

> 本文档是产品需求的唯一真相源。所有功能以本文档的 P0/P1/P2 分级为准；未列入本文档的需求不进入开发。

## 1. 产品定位与边界

### 1.1 定位

单店自提点餐的可复用模板。第一版只跑微信小程序，按多端标准编写，为后续扩展支付宝/抖音端预留适配层。

### 1.2 第一版明确不做

- 堂食扫码点餐、桌号/桌台管理
- 外卖配送、骑手调度、地址管理
- 多门店 / 多商家入驻
- 会员储值、积分、优惠券（仅留接口，不做界面）
- 排队取号、预订座
- 强制手机号授权、强制关注公众号

## 2. 角色与场景

| 角色 | 场景 | 核心诉求 |
|---|---|---|
| 顾客（自提） | 远程下单到店取 | 下单时选"自提"，凭订单号取餐 |
| 前台/收银 | 看单、改单 | 新单提醒、退单、异常处理 |
| 后厨 | 制作 | 实时新单、备注清晰、状态可点完成 |
| 店长 | 经营 | 改菜单、上下架、看今日营业数据 |

## 3. 功能分级

### 3.1 P0（第一版必须交付）

#### F-01 扫码/入口识别门店

- 顾客通过小程序入口（扫码或链接）解析 scene 参数，识别 merchant_id
- 异常处理：scene 无效、门店打烊

**验收用例：**

- Given 顾客通过有效入口进入，When 小程序启动，Then 应进入该门店的点餐页
- Given 门店已打烊，When 顾客进入，Then 应显示打烊提示且禁止下单
- Given scene 参数缺失或非法，When 小程序启动，Then 应显示错误页并提供重新进入入口

#### F-02 菜单浏览

- 按分类展示商品，支持分类切换
- 商品展示：图片、名称、价格、库存、售罄标识、上下架状态
- 售罄商品置灰且不可加购

**验收用例：**

- Given 门店有多个分类，When 顾客进入菜单页，Then 默认展示第一个分类且可切换
- Given 商品库存为 0，When 顾客浏览，Then 商品显示"已售罄"且加购按钮禁用

#### F-03 规格选择

- 通用规格组：杯型、甜度、冰度、加料（可配置）
- 规格选项可设置加价
- 加料类规格支持多选

**验收用例：**

- Given 商品有多个规格组，When 顾客点击加购，Then 弹出规格选择弹窗
- Given 某规格选项有加价，When 顾客选中该选项，Then 价格实时更新
- Given 规格未选完（必填组），When 顾客点击确认，Then 应提示且不允许加购

#### F-04 购物车

- 展示已选商品、数量、小计
- 支持增减数量、删除
- 支持订单备注

**验收用例：**

- Given 购物车有商品，When 顾客点击结算，Then 应进入确认订单页
- Given 顾客清空购物车，When 查看购物车，Then 显示空状态且结算按钮禁用

#### F-05 下单与支付

- 提交订单时预扣库存、生成 out_trade_no
- 调起微信支付（JSAPI）
- 到店支付兜底开关（商家可配置）
- 支付回调验签、幂等处理

**验收用例：**

- Given 顾客提交订单，When 支付成功，Then 订单状态变为待接单且库存扣减成功
- Given 微信支付回调重复到达，When 服务端处理，Then 订单状态不重复变更且不重复发货
- Given 商家开启到店支付，When 顾客下单，Then 可选"到店支付"且订单状态为待支付（到店）

#### F-06 订单状态流

- 状态：待接单 → 制作中 → 可取餐 → 已完成
- 额外状态：已取消、退款中、已退款
- 状态变更通过 WebSocket 实时推送到顾客端和后厨

**验收用例：**

- Given 顾客下单成功，When 商家接单，Then 订单状态变为制作中且顾客端实时收到通知
- Given 订单制作完成，When 后厨点击完成，Then 状态变为可取餐且顾客端收到取餐通知
- Given 待接单订单，When 商家取消，Then 状态变为已取消且库存释放

#### F-07 商家端：订单管理

- 新单提醒（声音 + 角标）
- 接单、完成、取消、退款申请
- 小票打印

**验收用例：**

- Given 有新订单，When 商家端打开，Then 新订单高亮且有提示音
- Given 商家点击接单，When 操作成功，Then 订单状态变更为制作中
- Given 商家点击打印，When 打印机在线，Then 小票正常打印

#### F-08 菜单管理

- 分类：新增、编辑、排序、显示/隐藏
- 商品：名称、图片、价格、库存、上下架、所属分类
- 规格组与规格选项的增删改

**验收用例：**

- Given 店长新增商品，When 填写完整信息并保存，Then 商品出现在对应分类下
- Given 商品被下架，When 顾客浏览菜单，Then 该商品不展示
- Given 店长调整库存，When 保存，Then 顾客端展示的库存实时更新

#### F-09 营业设置

- 营业中/打烊切换
- 门店公告

**验收用例：**

- Given 店长切换为打烊，When 顾客进入，Then 显示打烊提示且禁止下单

### 3.2 P1（第二版）

- 堂食扫码点餐、桌台管理
- 加菜、催单、呼叫服务
- 热销/推荐、搜索
- 今日营业额、订单数、时段分布、热销排行
- 店长/店员权限分离
- 打印机多设备、分单打印（吧台/后厨分开）

### 3.3 P2（以后再说）

- 会员、积分、优惠券、次卡
- 多门店、连锁总部看板
- 抖音/支付宝端

## 4. 非功能需求

| 编号 | 指标 | 目标 |
|---|---|---|
| NF-01 | 首屏菜单加载 | < 1s（菜单走缓存，图片 CDN） |
| NF-02 | 订单状态推送延迟 | < 3s（WebSocket） |
| NF-03 | 支付回调幂等 | 重复回调不产生副作用 |
| NF-04 | 库存防超卖 | 预扣 + 超时释放 |
| NF-05 | 弱网兜底 | 提交失败可重试，不重复下单 |
| NF-06 | 合规 | 最小化授权、隐私政策页、资质公示入口、不收集非必要信息 |

## 5. 术语表

| 术语 | 含义 |
|---|---|
| scene | 微信小程序入口参数，编码 merchant_id |
| out_trade_no | 商户订单号，全局唯一 |
| 预扣库存 | 下单时锁定库存，支付成功后正式扣减，超时未支付则释放 |
| 自提 | pickup，顾客远程下单到店自取 |
